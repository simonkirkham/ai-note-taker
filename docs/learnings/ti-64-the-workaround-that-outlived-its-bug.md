# Learnings: TI-64 — pre-commit publishes all three Lambda assets

**Tier 2** — a role rule was applied (Pip pre-PR self-check item 12) and there is a non-obvious *why* behind choosing publish-if-absent over publish-always.

- **The fix was 14 lines and cost four review rounds, because the workaround it deletes was written down in four places and each was found by somebody else.** `README.md`, `CLAUDE.md` `## Worktrees`, `CLAUDE.md` `## How to run`, and that section's `cdk deploy` step all told the reader to publish only `src/Api` — two found by the reviewer, two by the orchestrator, none by me. A change that removes a manual step is only half-shipped while the instruction to perform it is still in the file every agent reads at session start: the step keeps being executed, and `main` documents a workaround for a problem that no longer exists. Worse, two of those passages were wrong *independently of the hook* — a manual `cdk synth` from a fresh clone hit the identical `Cannot find asset` error, where no hook can help. **Action:** added item 12 to Pip's pre-PR self-check in [`agent-roles.md`](../../.claude/skills/.agent/generic/agent-roles.md) — when a change removes a documented manual step, grep the repo for that step and fix every hit in the same PR — Done.

- **A gate that only needs an artefact to *exist* should not pay to rebuild it.** `cdk synth` fingerprints each asset directory but never validates its contents, so a stale publish gates exactly as well as a fresh one. Publishing all three on every infra-touching commit — the fix the TI row proposed — would have been a permanent tax for zero extra signal. Publish-if-absent costs ~48 s once per worktree and two `test -f` calls forever after, and `cdk synth` still runs unconditionally, so nothing is silently skipped. **Action:** the reasoning is in the hook comment itself, next to the code it justifies, rather than only in this doc — Done.

- **The residual that choice creates was named rather than discovered later.** Publish-if-absent means a worktree now reliably holds artefacts that are never refreshed, so a by-hand `cdk deploy` from one can package stale code where a fresh worktree used to fail loudly. CI is unaffected (both workflows publish all three every run). **Action:** `README.md` and `CLAUDE.md` `## How to run` now say to re-run the publish loop before `cdk deploy`; recorded as a named residual in the PR body — Done.

- **`pr.yml` paths-ignores `.githooks/**`, so a green check list on this PR proved nothing about the changed file.** The only evidence was running the hook: red in a fresh worktree before the change, green in a second zero-artefact worktree after it, and still red with a defect injected into the stack's asset path so the guard was shown it could still fail. The third run is the one that mattered — publish-if-absent is exactly the shape of change that could have quietly disarmed the gate instead of fixing it. **Action:** said so in the PR body in place of leaning on the green ticks — Done.

- **A documented publish that does not match CI's publish is a silent performance regression, not a style nit.** Every by-hand publish in the docs omits `-r linux-x64 --self-contained false`, which `pr.yml` and `deploy.yml` use to ReadyToRun-precompile the API Lambda — the thing TI-35 shipped to cut first-request JIT. A manual `cdk deploy` from a clone undoes it and leaves prod that way until the next CI deploy. **Action:** filed as [TI-72] with the fix direction of a single `scripts/publish-lambdas.sh` that docs, hook and workflows all call, so the flags exist once — Done (filed, not fixed; out of this PR's scope by the orchestrator's call).
