# Learnings: CHANGE-43 — the build stamp links to its pipeline run

- **A hover state can quietly undo a measured decision.** The first cut coloured the hover `--color-primary`, which measured 3.19–4.10:1 in 4 of the 17 themes — under the 4.5:1 bar the resting colour had been chosen (and documented) to clear. Nothing automated catches it; a reviewer measured it in a browser. **Action:** hover keeps `--color-text` (9.48:1 at worst) and the underline carries the affordance; the measurement now sits in the CSS comment so the next person sees why not — Done.
- **A pure predicate with six specs still proves nothing about the wiring around it.** The URL check was well covered; the part that hands the URL to the system browser had no test, and its failure mode is a link that silently does nothing. **Action:** two tests drive the real desktop app — one asserts an allowed link reaches the browser hand-off, one asserts anything else opens nothing and no window appears — Done.
- **A test written after the code and passing first time is not yet evidence.** The Electron binary cannot start in this environment (missing system libraries), so "run it locally and watch it fail" was not available. **Action:** pushed a commit that disabled the hand-off, read the shared build's log — exactly those 2 tests failed and the other 165 passed — then reverted it. A build run is a usable red-proof when the local machine cannot run the test — Done.
- **A fixed sleep in a negative test can only ever produce a false pass.** The "opens nothing" control waited 500 ms. **Action:** it now fires the allowed URL as a flush and waits for that to arrive, so the absence is asserted at a point in time that is actually defined — Done.
- **Name what the link opens, not "this run".** The hover listed the installer version (numbered by the packaging run) next to a link pointing at the release's run — two different runs, one sentence. **Action:** the hover says "click to open this release" — Done.
